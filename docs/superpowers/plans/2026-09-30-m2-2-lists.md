# M2-2 — Lists Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The list page matches spec §9.2:
- a typed filter bar with removable chips;
- columns people can show, hide, reorder and resize, plus a density switch, remembered per resource;
- row selection with a bulk delete bar;
- a quick-view sheet on row click;
- cells edited in place (`list.editable`);
- proper loading, empty and error-with-retry states.

**Architecture:**
- **Server:**
  - `POST /resources/:r/bulk-delete` answers `{ ok, failed }` as spec §11 describes for bulk results. Each id runs in its own write (hooks, `query()`, soft delete and versions all apply), so one failure never undoes the others.
  - `list.editable` goes into the schema, and editable cells save through the normal PATCH (DTO, relation checks, `If-Match`).
- **UI state:**
  - Filters stay in the URL.
  - Column preferences live in localStorage per resource (per user in M3) through a small store like the nav state.
  - Chips are derived from the URL, so a shared link shows the same chips.
- **UI parts:** the sheet and menus use the Radix primitives already in the UI's devDependencies (`radix-ui`: Dialog, DropdownMenu, Checkbox), so there are no new packages.

**Tech Stack:** unchanged (no new dependencies).

**Spec:** §9.2 (server-side pagination, sort, search in the URL; typed filter bar with removable chips; column visibility/order/width and density persisted per user; row selection → bulk action bar; `list.editable` cell editing; quick-view Sheet on row click; empty, skeleton-loading and error-with-retry states), §11 (bulk results `{ ok: [ids], failed: [{ id, code, message }] }`), §10.1 (`list_editable`). Plan 2 of 4 for M2.

## Global Constraints

- All earlier constraints apply:
  - exact pins, logical utilities only (the i18n test enforces it);
  - every visible string through `t()`, in `en` and `fa`;
  - the error contract;
  - per-app test databases;
  - no AI attribution;
  - never commit `.idea/`, `.serena/` or the local Playwright config.
- Bulk delete takes at most 100 ids per request (a list page) and returns results in request order.
- `list.editable` fields must be in `form.update` and of an inline-editable type: string, number, decimal, bigint, boolean, enum, date. Anything else is a boot error with a hint.
- Keyboard access:
  - the quick-view sheet opens from a focused row with Enter, closes on Escape, and returns focus to the row;
  - editable cells commit with Enter and cancel with Escape;
  - selection checkboxes have accessible names.

## Review Focus

1. **Bulk delete of a mixed selection** (one active product the service refuses, one draft, one already gone) deletes the draft, reports the other two with their messages, and leaves the list consistent (Postgres, MySQL, SQLite). → Task 1.
2. **An inline edit that fails** (validation, business rule or stale version) shows the error on the cell and keeps the old value; a success updates the row in place without reloading the page. → Task 5.
3. **Chips from a shared URL** (enum `in`, range, relation, `isNull`) show readable labels (relation titles fetched), and removing one chip removes only that filter. → Task 2.
4. **Hidden and reordered columns survive a reload**; a column the schema no longer has is dropped silently. → Task 3.

### Task 1: Bulk delete and `list.editable` in core

- [ ] **Tests first** (`bulk-and-editable.test.ts`, every database, demo-like fixture with a refusing service):
  - `POST …/bulk-delete { ids }` → `{ ok: [...], failed: [{ id, code, message }] }` in request order (Review Focus 1);
  - soft-deletable resources move records to the trash;
  - more than 100 ids, or ids of the wrong shape, are 422;
  - ids outside `query()` are reported `NOT_FOUND`.
  - Schema tests:
    - `list.editable: ['status', 'stock']` is in the schema;
    - a field outside `form.update` is a boot error;
    - so is a json or relation field.
- [ ] **Implement:**
  - `AdminApiService.bulkDelete(name, ids, ctx)` loops `remove()` per id, mapping each error through `toErrorResponse` without logging expected 4xx.
  - The route `POST /api/resources/:resource/bulk-delete`.
  - `ListConfig.editable` with validation.
- [ ] **Verify** on all three databases, then commit `feat: bulk delete with per-record results; list.editable`.

### Task 2: Typed filter bar with chips

- [ ] **Tests first.** `filter-chips.test.ts`, URL → chips:
  - `filter[status][in]=draft,active` → `Status: draft, active`;
  - `filter[price][gte]=5&filter[price][lte]=10` → `Price: 5 – 10`;
  - `filter[notes][isNull]=true` → `Notes: empty`;
  - relation ids resolved with titles (`#id` until loaded);
  - `search` → a search chip;
  - removing a chip lists exactly the params to delete.
- [ ] **Implement:**
  - An enum filter becomes a multi-select (`in`, a popover of checkboxes) when `in` is allowed, else a single select.
  - Nullable fields get an "empty / not empty" choice (`isNull`).
  - A chip row under the bar, each chip with a remove button named `Remove filter <label>`.
  - `Clear filters` stays.
- [ ] **Verify** (unit tests, typecheck, build, E2E filters), then commit `feat(ui): typed filter bar with removable chips`.

### Task 3: Columns, density and list states

### Task 4: Selection, bulk delete bar, quick view

- [ ] **Implement:**
  - A checkbox column (select page / select row, with names).
  - A bulk bar showing "N selected", "Delete selected" (with confirmation) and "Clear selection". Results show as a summary ("2 deleted, 1 failed: …").
  - Selection clears on page or filter change.
  - Row click, or Enter on a focused row, opens a quick-view Sheet (Radix Dialog), which shows fields with the same formatting as cells, "Edit", "Close", and related links. The first-column link still opens the edit page. Mobile cards keep navigating.
  - Keyset lists keep selection per page.
- [ ] **E2E:**
  - select two drafts and one active product → bulk delete → summary shows 2 deleted, 1 failed with the service's message;
  - the quick view opens from a row with the keyboard and closes with Escape, returning focus.
- [ ] **Verify**, then commit `feat(ui): row selection with bulk delete; quick-view sheet`.

### Task 5: Inline editing, demo, docs

  - Escape cancels;
  - errors show under the cell and keep the old value;
  - a success patches the cached list row (Review Focus 2).
- [ ] Demo: `ProductAdmin.list.editable = ['status', 'stock']`.
- [ ] **E2E:**

  - hidden columns survive a reload (Review Focus 4);

- [ ] Docs: README (lists section), CLAUDE.md, and m0-followups.
